# Harness engineering: leveraging Codex in an agent-first world

Source: https://openai.com/index/harness-engineering/

The article "Harness engineering: leveraging Codex in an agent-first world" details OpenAI's experiment in building a software product with zero lines of manually written code. The core philosophy shifted the engineer's role from writing code to designing environments, specifying intent, and building feedback loops for Codex agents.

### Key Technical Concepts & Strategies
*   **Agent-First Development:** Every artifact—application logic, tests, CI/CD, and documentation—is generated by Codex. Humans "steer" via prompts while agents "execute."
*   **The "Ralph Wiggum Loop":** An iterative cycle where Codex reviews its own changes, requests peer agent reviews, and responds to feedback until all automated reviewers are satisfied.
*   **Progressive Disclosure:** Instead of a monolithic instruction file, the system uses a 100-line `AGENTS.md` as a "table of contents" pointing to a structured `docs/` directory (the "system of record").
*   **Agent Legibility:** The codebase is optimized for model reasoning. This includes using "boring" technologies with stable APIs and reimplementing dependencies to ensure they are fully discoverable within the repository.
*   **Automated "Garbage Collection":** Background agents scan for "AI slop" or architectural drift and open refactoring PRs to maintain "golden principles" and technical debt.

### Architectural Details
*   **Rigid Layered Domain Architecture:** Business domains are divided into fixed layers (Types → Config → Repo → Service → Runtime → UI).
*   **Strict Dependency Enforcement:** Code can only depend "forward" through layers. Cross-cutting concerns (auth, telemetry) must enter through explicit "Providers."
*   **Mechanical Invariants:** Custom, agent-generated linters and structural tests enforce architectural boundaries and "taste" (e.g., naming conventions, file size limits).
*   **Observability for Agents:** The runtime is wired with Chrome DevTools and local observability stacks (PromQL/LogQL), allowing agents to validate UI behavior and performance metrics (e.g., "ensure startup < 800ms") autonomously.
